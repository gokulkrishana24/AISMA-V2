## 1. Executive Summary

## 3. Security, Multi-Tenancy & Governance Audit

### 3.1 Fail-Closed Security Policy
The platform implements an uncompromising fail-closed architecture:
1. **Unregistered Tenant Check:** Any API request presenting an invalid or mismatched `X-Business-Id` header is immediately rejected with `403 Forbidden` (`require_tenant_access`).
2. **Emergency Killswitch:** When the killswitch is engaged for a business, all automated publishing and approval decisions are blocked immediately at the API gateway layer.
3. **Daily Budget Enforcement:** Daily token, action, and financial cost limits are verified deterministically before orchestrator task dispatch.
4. **Token Encryption at Rest:** External platform OAuth tokens (LinkedIn, Meta, X) are symmetrically encrypted in the database using 256-bit AES/Fernet encryption via `CredentialVault`.

### 3.2 Cryptographic Audit Trail
All approval decisions, killswitch toggles, and multi-agent task completions write an entry to the SHA-256 audit ledger:
$$\text{Entry Hash} = \text{SHA-256}(\text{prev\_hash} \parallel \text{timestamp} \parallel \text{business\_id} \parallel \text{action} \parallel \text{details})$$
Verification is available via `POST /api/v1/governance/audit/verify`, providing mathematical proof of chain integrity.

## 4. Deterministic Analytics vs. LLM Hallucinations

A critical design requirement of AISMA v2 is that **financial and marketing attribution metrics are never generated by LLMs**. 

The `DeterministicROIEngine` (`src/analytics/roi.py`) executes formulated Python mathematics:
- **ROAS:** $\text{Revenue} / \text{Ad Spend}$
- **ROI:** $\frac{\text{Revenue} - \text{Total Costs}}{\text{Total Costs}} \times 100\%$
- **CAC:** $\text{Total Acquisition Cost} / \text{New Customers}$
- **LTV:CAC Ratio:** $\text{Customer Lifetime Value} / \text{CAC}$

Every computed report generates a deterministic SHA-256 audit hash of its inputs and results, guaranteeing reproducibility across audit reviews.

## 5. Deployment Topology & CI/CD Verification

The system is fully containerized across three core microservices in `docker-compose.yml`:
1. **`backend` (Port 8000):** FastAPI application with healthcheck `/api/v1/health`.
2. **`frontend` (Port 3000):** Next.js 14 App Router production runner.
3. **`ollama` (Port 11434):** Dedicated containerized Ollama local inference service with persistent volume storage for AI weights.

Continuous integration is enforced via `.github/workflows/ci.yml`, running parallel validation pipelines for Python (Ruff, Pytest regression) and TypeScript (TypeCheck, ESLint, Next.js build).
